### 用户已拍板的三个决定（2026-09-19）

1. **时间只用"等待时间"一个概念**：不再区分"动手时间/等待时间"，每步只记"这一步要多久"（腌制 10 分钟、热油 2 分钟、翻炒 3 分钟）。→ 不新增 `waitMinutes`，沿用现有 `minutes`，只把语义写清楚。

## 1. 目标与非目标

### 目标

手机放在灶台边，你**自己滚动、自己掌握节奏**，页面不抢控制权：

1. **滚过头也能一秒回去**：滚动时顶部始终显示"第 3 步 / 共 5 步 · 步骤名"，点一下平滑回到当前未完成的那一步。
2. **做菜节奏不被打断**：不自动折叠、不自动推进，页面结构在操作过程中保持稳定，用户自己掌握滚动。
3. **需要等的步骤能一键计时**：步骤时长（腌制、焖煮、焯水…）点一下开始倒计时，到点响铃 + 震动 + 视觉提示；息屏或切走再回来，剩余时间是准的。
4. **做菜期间屏幕不熄灭**（详情页默认开启，可手动关）。
5. **份量按菜谱原文显示**：显示 `servings` 与原始食材用量，不提供档位，也不自动换算。
6. **看得见厨具**：进详情页就知道要不要用烤箱/蒸锅，避免备料到一半发现没工具。

### 非目标

- **不做**全屏覆盖层的"做菜模式"，**不做**左右滑动切步，**不做**自动推进到下一步。
- **不做**语音控制：厨房噪音下不可靠，成本也不划算。
- **不做**菜谱的网页录入/编辑（属 M5，另立规格，且属 T2 需要 ADR）。
- **不做**营养/热量计算。
- **不动**列表页与搜索交互。
- **不新增**"动手时间/等待时间"两个字段（用户已明确不需要）。

## 2. 用户场景与状态流

**场景**：晚饭时间，手机放在料理台支架上，人站在灶台与案板之间，距离手机 0.5–1.5 米，手上可能沾水沾油。注意力在锅里。

```text
详情页（单页滚动，不切换视图）
  ├─ 顶部：返回 ｜ 屏幕常亮开关
  ├─ 菜名 / 摘要 / 元信息（含菜谱记录的份量）
  ├─ 食材（按菜谱原文显示）+ 厨具
  ├─ 吸顶条：进度条 · 3/5 · 当前步名   ← 点击 → 回到当前步
  ├─ 做法（步骤卡片：序号 · 小标题 · 时长按钮 · 火候 · 正文 · 小提醒）
  │    ├─ 点时长按钮 → 开始倒计时（按钮变 02:31）
  │    ├─ 点步骤卡片 → 标记完成（灰化 + 划线，位置不动）
  │    └─ 倒计时结束 → 响铃 + 震动 + 闪烁提示
  └─ 小贴士 / 来源
```

**结束条件**：返回列表、或浏览器返回。做菜进度在当前会话内保留（沿用已有 sessionStorage 机制）。

## 3. 交互细节与状态

### 3.1 详情页头部与元信息

| 状态 | 表现 | 说明 |
| --- | --- | --- |
| 默认 | 分类 / 份量 / 难度 / 耗时徽标 | 已有 |
| 有 `equipment` | 元信息下方一行"厨具：炒锅、锅铲" | 无该字段则不显示，不留空行 |
| 屏幕常亮开启 | 顶部开关显示"常亮 · 开" | 默认开；不支持时见 §5 |
| 屏幕常亮关闭 | 顶部开关显示"常亮 · 关" | 选择写入 localStorage，下次进详情页沿用 |

### 3.2 份量显示（**不做换算**）

**当前规则（2026-09-20）：不做自动换算。** `servings` 和食材用量按菜谱原文显示。CB-004 曾短暂恢复缩放，
后经独立复核 P1-2 与用户确认后撤回，详情见 [CB-004](CB-004-serving-scale.md) 和[修复记录](../verification/overall-review/FIXES.md)。

理由：`servings: 2` 是"**一男一女的实际食用量**"这个**家庭基准**，不等于批准任意倍数缩放；
自动换算还会与步骤文案里写死的数字直接矛盾，让人误以为用量正确。

| 状态 | 表现 | 说明 |
| --- | --- | --- |
| 默认（唯一状态） | 食材区标题显示菜谱记录的份量，用量**按菜谱原文原样显示** | 不做任何换算、不提供档位 |
| 缩放的后续可能 | 当前不做；如要重启，先立规格并处理步骤中的固定用量 | 见 [OPEN_QUESTIONS Q10](../OPEN_QUESTIONS.md) |

**用量显示规则**（实现为纯函数，见 §7）：

- 数值 + 单位原样输出（`3g`、`20ml`、`4片`）。
- 字符串用量原样输出（"适量""少许"）。
- 缺 `amount` 但有 `unit` → `— g`；两者都缺 → `适量`。
- 单位永不换算。

**由此产生的内容纪律（写进 [DATA_MODEL](../DATA_MODEL.md)）**：食材表与步骤文案里的数字必须互相自洽，
且**步骤里出现的时间数字必须与该步 `minutes` 相同**（`minutes` 同时是该步的计时默认值）。

### 3.3 吸顶进度条（解决"滚过头"）

| 状态 | 表现 | 说明 |
| --- | --- | --- |
| 滚动到做法区域之前 | 不显示（避免遮挡） | 实现用 `position: sticky` 且**只在做法区域内吸顶**（不需要 IntersectionObserver） |
| 滚动进入/越过做法区域 | 吸附在页面顶部：`进度条` + `3/5` + 当前步小标题（无标题则显示序号） | 不遮挡正文内容（页面给顶部留出等高间距） |
| 点击 | 平滑滚动到当前未完成步骤 | 找不到未完成步骤时滚到最后一步 |
| 全部完成 | 显示"全部完成 · 5/5"，点击滚回第一步 | |

### 3.4 步骤卡片

| 状态 | 表现 | 说明 |
| --- | --- | --- |
| 默认 | 序号 · 小标题 · `时长`按钮 · 火候 · 正文 · 小提醒 | 无时长的步骤不显示时长按钮 |
| 有 `minutes` | 显示为可点按钮 `⏱ 10 分钟` | 点一下开始倒计时 |
| 倒计时中 | 按钮变为 `09:58` 并显示进度 | 同一时间**只允许一个计时器**，点另一个步骤的时长会切换（先确认再切换？不需要，直接切换并给视觉反馈） |
| 计时结束 | 按钮变为「时间到」并闪烁；响铃 3 声 + 震动；点击按钮可停止/清除 | 页面在后台时，回到前台补一次提示 |
| 点卡片其余部分 | 标记完成 / 取消完成 | 已有行为 |
| 已完成 | 保持原样，灰化 + 划线，**位置不变**（不折叠，避免内容跳动让人找不到位置） | 二次反馈后取消折叠 |
| 正在计时的步骤被标记完成 | 计时继续，不中断 | 避免做菜时误操作导致计时丢失 |

### 3.5 尺寸要求（与实现对齐后的策略）

- **主要操作 ≥ 44px**：步骤卡片、时长/计时按钮、返回列表、常亮开关、字号按钮。
- **次级控件 ≥ 40px**：筛选 chip、份量/面板内的开关 chip（浏览时用手指点，40px 足够；厨房里的主操作才必须 44px）。
- 时长按钮与卡片其他区域**互不干扰**（两者是并列按钮，不做嵌套），避免点计时把步骤标成完成。
- 手机竖屏无横向滚动。
- 动画遵守系统 `prefers-reduced-motion`（到点提示改为静态描边，不靠闪烁传达信息）。

## 4. 数据与接口变化

### 新增字段（可选，向后兼容）

| 字段 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- |
| `equipment` | 菜谱级 | `string[]` | 需要的厨具，如 `["炒锅", "锅铲", "锅盖"]` |

```json
{
  "id": "example-dish",
  "equipment": ["炒锅", "锅铲"],
  "steps": [
    { "text": "加姜片、料酒抓匀，放 10 分钟", "title": "腌制", "minutes": 10 }
  ]
}
```

### `minutes` 的语义（本规格明确，不新增字段）

`minutes` = **这一步大概要多久**，包含等待：

- 腌制 10 分钟 → `"minutes": 10`
- 热油 2 分钟 → `"minutes": 2`
- 翻炒 3 分钟 → `"minutes": 3`

它同时是**步骤时长显示**与**一键计时的默认时长**。需要计时但原文没写时长的步骤，由菜谱内容补 `minutes`（属内容整理，不是代码改动）。

### 接口

- `GET /api/recipes/:id` 直接返回 `equipment`，**无新端点**，列表接口不变。
- 服务端不计算份量；前端按菜谱原文显示 `servings` 和食材用量。

### 向后兼容检查

- 现有 2 个样例文件不含 `equipment` 时行为不变（不显示厨具行）→ **本次会顺手给两个样例补上 `equipment`**，并核对每步 `minutes` 语义。
- zod 新增字段可选，`npm run check:data` 对不带头字段的文件仍通过。

## 5. 失败、降级与边界

| 情形 | 期望行为 | 用户可见反馈 |
| --- | --- | --- |
| Screen Wake Lock 不支持 / 被拒（http 非安全上下文、省电模式） | 其他功能照常；常亮开关显示"常亮不可用"/"常亮被拒" | **点击常亮开关时**提示原因（与开关方向无关，避免"点了没反应"），建议手动关自动锁屏 |
| `navigator.vibrate` 不支持（iOS Safari） | 只响铃 + 视觉提示 | 无额外提示 |
| Web Audio 被自动播放策略阻止 | 退回视觉闪烁提示 | 明确显示「时间到」 |
| 计时期间息屏 / 切走应用 | 用**目标时间戳**计算剩余，回来后显示真实剩余 | 已结束则显示「时间到」并补提示 |
| 步骤没有 `minutes` | 不显示时长按钮，不显示计时入口 | 无 |
| `minutes` 为 0 或异常值 | 不显示计时入口（校验层已限制为非负有限数） | 无 |
| 食材 `amount` 是字符串 | 按显示规则原样显示，不做换算 | 无 |
| 快速连点步骤卡片 | 状态切换幂等，不出现重复计时器 | 无 |

## 8. 风险、回滚与依赖

- **风险 1**：吸顶条遮挡内容。缓解：只在做法区域吸顶（区域内 sticky），并在滚动到当前步时用 `block: "center"` 留出空间。
- **风险 2**：局域网 http 下 Wake Lock 大概率被拒（需安全上下文）。缓解：按 §5 降级并给提示；不为此引入 HTTPS（用户已决定）。
- **风险 3**：计时提醒在嘈杂厨房可能听不见。缓解：响铃 + 震动 + 视觉三重提示；若试做后仍不够，再考虑"到点后页面保持高亮直到手动确认"。
- **回滚**：纯前端 + 一个可选字段，回滚即回退代码版本；数据文件无需回滚（旧代码忽略 `equipment`）。
- **依赖**：M1–M3 已完成；不新增第三方依赖（Web Audio / Vibration / Wake Lock 均为浏览器原生；吸顶用 CSS `position: sticky`）。

### 实现过程中发现并修正的偏差

按 AGENTS.md“实现与规格不一致就停下来说明”的约定记录：

1. **换算格式过于“机器味”**：原规格（`≥10` 取整）在基准 3 人→4 人时产生 `667g`、`6.7ml`、`5.3 片姜`。已改为分级取整（≥100 取整到 10；2–100 取整），并明确“比例为 1 时输出与原文完全一致”。规格 §3.2 已同步更新。
2. **食材分组顺序反了**：原 `GROUP_ORDER` 把`调料`排在`腌料`之前，结果“姜、料酒”跑到“生抽、盐”后面。已改为按做菜顺序：主料 → 腌料 → 调料 → 汤底。
3. **常亮不可用时“点了没反应”**：原实现只在“打开开关”时给提示，于是第一次点击变成“关”且无解释。已改为：只要能力不可用，点击就说明原因（与开关方向无关）。规格 §5 已同步。
4. **份量选择不持久（验收发现的真 bug）**：写入用了 sessionStorage、读取用的是 localStorage，原因是 `writeStored` 的存储位置是默认参数，调用时忘传就静默写错地方。**已做结构性修复**：把存储位置写进 `STORAGE_KEYS` 注册表（每个键自带 `kind`），调用方不再传 kind——这类错从此不可能发生。修复后实测：返回列表再进→保留、刷新页面→保留。
