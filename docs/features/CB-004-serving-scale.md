## 1. 背景：为什么"撤销换算"后又恢复

CB-001 三次修订时撤销了份量换算，理由有两条：① 两人份是家庭基准，不是"任意倍数"的授权；② 换算后与**步骤文案里写死的用量**直接矛盾（复核 P1-2）。

**现在用户给出了明确口径**（这正是当初缺的东西），并且菜单里绝大多数菜的基准是 1 人份或未声明，只显示"2 人份"确实不够用。所以恢复换算，并同时解决当初的矛盾点。

## 2. 缩放规则（用户授权的口径）

> **多一个人，多 0.5 倍。**

| 人数 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- |
| 倍数 | **1.0×** | **1.5×** | **2.0×** | **2.5×** |

`倍数 = 1 + (目标人数 - 基准人数) × 0.5`

- 档位**以每道菜自己的基准份量为起点**向上排列：基准 2 → `2/3/4/5`；基准 1 → `1/2/3/4`；基准 3 → `3/4/5/6`。
- **不提供低于基准的档位**（不做"砍半"，与 CB-001 §3.2 的结论一致）。
- 基准为 1 的菜（导入菜里 30 道明确是 1 人份）同样按此规则向上。

### 用量换算与显示

| 原始写法 | 处理 | 例（1.5×） |
| --- | --- | --- |
| 数字（69%） | × 倍数后按"像人写的数"取整 | `200g → 300g`；`3g → 4.5g`→`4.5g` |
| 范围 `10-15ml`（5%） | **两端同时缩放** | `→ 15-23ml` |
| 中文数字 `一根`（1%） | 转数字后缩放，输出阿拉伯数字 | `一根 → 1.5根` |
| 无用量 / `适量`（23%） | **原样不动** | `适量 → 适量` |

取整规则沿用 CB-001 的实现（`formatScaledAmount`）：≥100 取整到 10；2–100 取整；1–2 保留 1 位小数；<1 保留 2 位小数。

**基准份量（1.0×）下显示与原文完全一致** —— 不动任何数字。

## 3. 步骤文案里的用量（当初矛盾的正面解决）

导入菜谱的步骤里有写死的用量（"热锅倒 15ml 油"），缩放后与食材表不一致。**不重写原文**，而是把风险说清楚：

| 状态 | 表现 |
| --- | --- |
| 选中基准份量 | 不显示任何提示 |
| 选中非基准份量 | **做法区顶部出现一行提示**：`步骤里的用量按 2 人份写，当前显示 4 人份 —— 请按上面的食材表取量` |

提示样式：与现有 `.notice` 一致，黄色（warn）而不是红色（这不是错误，是提醒）。

## 4. 交互与持久化

- 食材区标题右侧一排档位按钮（沿用已删除的 chip 样式）；当前档位高亮。
- 选择按菜谱记进 `localStorage`（键 `cookbook:servings:<id>`，走既有 `STORAGE_KEYS` 注册表，自带 kind）。
- 切回基准档位 = 清除该菜的记录。
- 换算后用量给一次 220ms 高亮（沿用原实现）。

## 5. 失败、降级与边界

| 情形 | 行为 |
| --- | --- |
| `localStorage` 不可用 | 换算照常工作，只是不记住选择（不提示，与字号等一致） |
| 基准份量异常（0/负数） | 档位退化为 `1/2/3/4`，倍数按 1 计算 |
| 倍数计算出现浮点尾巴 | 由取整规则兜住（`0.6666` → `0.67`） |
| 菜谱 `servings` 缺失 | schema 保证必有（servings 是必填） |

## 6. 验收标准

- [ ] 基准 2 人份的菜：档位显示 `2 / 3 / 4 / 5`，选中 2 时用量与原文**完全一致**。
- [ ] 选 3 人份（1.5×）：`200g → 300g`；`3g → 4.5g`；`盐 适量` 不变。
- [ ] 选非基准档位时，做法区顶部出现"步骤里的用量按 X 人份写"的提示；切回基准后消失。

- [ ] 中文数字用量（`一根`）能换算，且换算后是阿拉伯数字。
- [ ] 基准份量为 1 的菜（如导入的"白灼虾"）档位是 `1 / 2 / 3 / 4`。
- [ ] 选择在刷新后保持；切回基准后记录被清除。
- [ ] `npm run typecheck`、`npm test`、`npm run check:data` 全绿。

## 8. 风险与回滚

- **风险 1**：0.5 倍规则未必适合所有菜（汤类、主食的缩放可能不合直觉）。缓解：这是用户明确给的口径；若实际用起来不对，改一个常量即可（`SCALE_STEP = 0.5`）。
- **风险 2**：步骤文案的数字仍是"按基准份量写"的，用户可能忽略提示。缓解：提示放在做法区顶部（进入做法区第一眼就能看到），而不是藏在角落。
- **回滚**：纯前端 + 一个常量，回退代码即可；数据文件不受影响。

## 9. 实施拆解

1. `scale.ts`：档位生成 + 四类用量换算 + 单测（先纯函数，后接界面）。
2. `IngredientList`：档位按钮 + 换算显示 + 高亮。
3. 页面：把档位状态提到 `RecipePage`（持久化），并把"步骤用量按基准写"的提示传给 `StepList`。
4. 抽样回归：基准档位下 5 道菜逐字比对导入结果。
