## 1. 目标

1. 详情页能**点赞**（计数）与**收藏**（开关），操作即时反馈。
2. 列表页把**收藏的、点赞多的菜排到最前面** —— 常做的菜不用每次搜索。
3. 两口子**共享同一份状态**（手机点的赞，电脑上也看得到）。
4. 写入失败必须看得见（不得静默成功）。

## 2. 非目标

- 不做用户账号、不记录"谁点的赞"（ADR-0003 明确不做）。
- 不做评论、评分（1–5 星）。
- 不做"最近浏览"（那是本地就够的事，另立规格）。
- 不做按赞排序的多种模式（只有一种默认排序）。

## 3. 交互细节

### 3.1 详情页

| 元素 | 状态 | 表现 |
| --- | --- | --- |
| 点赞 | 未点 | `👍 12`（灰色描边），点击后 +1 并变实心 |
| 点赞 | 已点（本机） | 实心；再点 -1（下限 0） |
| 收藏 | 未收藏 | `☆ 收藏`；点击后变 `★ 已收藏`（强调色） |
| 进行中 | 请求未返回 | 按钮禁用 + 半透明，防连点 |
| 失败 | 网络/服务端错误 | **明确提示"这次没能保存，请重试"，并把界面回滚到操作前的值**（不留假状态） |

### 3.2 列表页

- 卡片上显示：收藏标记（★，仅收藏时显示）与点赞数（仅 >0 时显示）。**不显示 0**，避免噪音。
- 排序：**收藏优先 → 点赞数降序 → 名称**（分类/标签筛选与搜索的叠加规则不变）。
- 排序在**服务端**做（`/api/recipes`），前端不重排 —— 与"搜索在服务端"的既有约定一致。

### 3.3 状态获取

- 前端启动时 `GET /api/user-state` 拿全量状态（371 道菜的状态文件很小，一次拿全最简单）。
- 列表接口的返回里**带上 `likes` 与 `favorite`**（服务端排序需要，前端展示也需要）。

## 4. 数据与接口

数据文件与接口按 [ADR-0003](../decisions/ADR-0003-write-operations-user-state.md) 执行：

```json
// data/user-state.json
{ "version": 1, "recipes": { "hong-shao-rou": { "likes": 3, "favorite": true, "updatedAt": "..." } } }
```

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/user-state` | 全量状态 |
| `POST` | `/api/recipes/:id/like` | `{ delta: 1 \| -1 }` |
| `POST` | `/api/recipes/:id/favorite` | `{ favorite: boolean }` |

- `id` 不存在 → 404；body 校验失败 → 400；写盘失败 → 503（**不用 500**，因为这是"暂时不可用"）。
- 写操作有**串行队列**（ADR-0003）：同时只有一个写在跑。

## 5. 失败、降级与边界

| 情形 | 行为 |
| --- | --- |
| `user-state.json` 不存在 | 视为空状态，首次写入时创建 |
| 文件损坏 | 另存为 `.broken` 后用空状态启动（不静默丢数据），日志 warn |
| 磁盘满 / 只读挂载 | 接口 503；前端提示；**界面回滚** |
| 同一个菜被两人同时点赞 | 计数串行累加（+1 与 +1 = +2），不会互相覆盖 |
| 点数降到负数 | 下限 0 |
| 菜谱被删除但状态里还有 | 状态保留（无害）；列表接口只返回存在的菜 |
| 状态文件里有不存在的 id | 忽略，不影响其他菜 |

## 6. 验收标准

- [ ] 详情页点赞 +1、再点 -1；刷新后保持（说明真的落盘了）。
- [ ] 收藏开关生效并在刷新后保持。
- [ ] **两台设备**（手机 + 电脑）：一台收藏，另一台刷新后也看到 ★ 与排序变化。
- [ ] 列表页：收藏的菜排最前；点赞多的排在点赞少的前面；两者都没有的按名称。
- [ ] 卡片上点赞为 0 时不显示数字，未收藏不显示 ★。
- [ ] 数据目录设为只读时（模拟写失败）：接口返回 503、前端明确提示且界面**回滚**，不出现"看起来收藏了其实没保存"。
- [ ] `data/user-state.json` 出现在 `data/` 备份里（打包 `data/` 即包含）。
- [ ] 容器：根文件系统仍只读；仅数据目录可写；写入路径为 `/data/user-state.json`。
- [ ] `npm run typecheck`、`npm test`、`npm run check:data` 全绿。

## 8. 风险与回滚

- **风险 1**：数据目录改为可写（架构变化）→ 已在 ADR-0003 记录代价与边界；容器根仍只读。
- **风险 2**：写接口无鉴权 → 同网段可点赞；与只读接口同一信任模型，局域网自用可接受。
- **风险 3**：排序把收藏顶到最前，可能让"搜索特定菜"时结果顺序意外。缓解：排序只在**无搜索词**时按收藏/点赞优先；有搜索词时按相关度（既有逻辑）。
  - 这条是本规格的**明确选择**，验收里也要覆盖。
- **回滚**：删掉写接口与状态文件即可回到只读；菜谱数据完全不受影响。

### 实现过程中修掉的一个真 bug

路由里**漏了排序调用**：`items: matched.map(...)` 直接返回，`sortByUserPreference` 没被调用 →
收藏的菜不会排到最前。原因是早先一次批量替换的**锚点没匹配上而静默失败**（无失败校验）。
已补上并复验；同时给后续所有批量替换加了锚点校验（不匹配就报错退出，不再静默）
