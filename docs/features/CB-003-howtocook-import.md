## 1. 背景与来源裁定

用户想"丰富菜单"，并提示可能有开源菜单。调研结论：

| 仓库 | 许可 | 裁定 |
| --- | --- | --- |
| [`Anduin2017/HowToCook`](https://github.com/Anduin2017/HowToCook)（62k★，"程序员做饭指南"） | **Unlicense（公有领域）** | ✅ **作为导入来源** |
| [`Gar-b-age/CookLikeHOC`](https://github.com/Gar-b-age/CookLikeHOC)（24.6k★，"像老乡鸡那样做饭"，源自老乡鸡《菜品溯源报告》） | **无 LICENSE**（README 亦无许可声明） | ❌ **不使用其内容**：无许可即默认保留所有权利。仅可参考其"按烹饪工艺分类"的组织方式 |

**这是本次的第一个决策**：内容来源必须许可清楚。HowToCook 是 Unlicense，法律上无需署名，但本项目仍会在每道菜的 `source` 字段与文档里注明来源——把出处写清是最低成本的正确做法。

### 关键发现：`每份` = 两人份

HowToCook 官方模板原文：

> 每次制作前需要确定计划做几份。**一份正好够 2 个人吃。**

而本项目的家庭基准也是 2 人份（用户确认："两人份就是一男一女"）。**两者对齐**，因此：

- 导入时**用量原样照抄**，`servings` 一律记 `2`；
- **不做任何倍数换算或取整**（这正是前几轮反复确认过的红线）。

## 2. 目标与非目标

### 目标

1. 把 HowToCook 的菜谱批量转成本项目的 JSON 格式，字段对齐、能通过现有校验与内容检查。
2. 导入结果**忠实于原文**：不重写用量、不改写步骤、不臆造元数据。
3. 有来源标注（`source`），能一眼看出哪些菜是导入的。
4. 导入器可重复运行、可限定范围（先小批验收、再全量）。

### 非目标

- **不导入** CookLikeHOC 的内容（无许可）。
- **不自动推断厨具**：只有 8/372 有独立「工具」小节；其余一律留空，食材表里能对上词表的词才挪进 `equipment`。
- **不引入图片展示**（属 M4）：本次只把成品图按 `data/images/<id>/cover.jpg` 落盘，界面暂不显示。
- **不做译文/改写/润色**：原文怎么写就怎么进 JSON。
- **不导入** `dishes/template/`（官方模板，不是菜）。

## 3. 字段映射规则

| HowToCook | 本项目 | 规则 |
| --- | --- | --- |
| 标题 `# 菜名的做法` | `name` | 去掉后缀"的做法" |
| 目录名 | `category` | `meat_dish`/`vegetable_dish`/`aquatic`→`家常菜`；`soup`→`汤羹`；`staple`→`主食`；`breakfast`→`早餐`；`dessert`→`甜品`；`drink`→`饮品`；`condiment`→`调料`；`semi-finished`→`半成品` |
| 首段描述 | `summary` | 取标题后的第一段纯文本（原样） |
| `预估烹饪难度：★★★` | `difficulty` | ★/★★→`1`；★★★→`2`；★★★★/★★★★★→`3` |
| 首段里的"约 N 分钟" | `cookMinutes` | 只在能明确解析到一个总时长时写入；否则省略 |
| `## 计算` 的条目 `豆腐 100 g` | `ingredients` | 拆成 `name` / `amount` / `unit`；范围（`10-15ml`）→ `amount` 用字符串 `"10-15"`（本项目允许字符串用量）；括号内容（`（可选）`、`（切丝）`）→ `note` |
| 食材名能对上厨具词表 | `equipment` / `equipmentAlternatives` | 命中词表（含 `蒸锅或电蒸炉` 这类"或"写法）→ 移出食材表，放进厨具；**其余一律不填** |
| `## 操作` 的编号项 | `steps` | 主行→`text`；行首粗体（`**准备酱汁**：`）→`title`；子要点→`tip` |
| 步骤里的时间 | `minutes` | **恰好一个**分钟数 → 取该值；**范围**（`15-20 分钟`）→ 取**下限**（先检查，避免糊锅）；只有秒（`30 S`）或没有 → 不填 |
| `![名称](./x.jpg)` | （落盘） | 复制为 `data/images/<id>/cover.jpg`；界面展示属 M4 |
| — | `source` | `HowToCook（Unlicense 公有领域）` + 仓库地址 |
| — | `tags` | **留空**：不臆造标签 |
| — | `id` | 菜名转拼音（`pinyin-pro`，仅 devDependency），冲突时加序号 |

## 4. 内容检查的规则升级（本规格的一部分）

现有 `content-lint.ts` 的规则是"文案里的分钟数必须与 `minutes` 相同"，它会把**时间段范围**（`焖 15-20 分钟`）判成"多个分钟数"而拒绝 —— 而 HowToCook 大量使用范围。因此同步放宽：

| 情形 | 现规则 | 新规则 |
| --- | --- | --- |
| 单个分钟数 | 必须 == `minutes` | 不变 |
| 范围 `a-b 分钟` | ❌ 报"多个分钟数" | ✅ 允许，要求 `minutes` 落在 `[a, b]` 内（导入取 `a`） |
| 同一步骤两个**不相连**的分钟数（`焯 2 分钟，再焖 5 分钟`） | ❌ 报错 | 仍报错（无法确定计时多久） |
| 文案有分钟但未填 `minutes` | ❌ 报错 | 不变 |

## 5. 失败、降级与边界

| 情形 | 期望行为 |
| --- | --- |
| 某道菜解析失败（格式异常） | 跳过该文件并在输出里列出原因，**不影响其他菜** |
| 同一菜名产生相同 `id` | 追加序号（`-2`、`-3`） |
| 图片不存在 | 不落盘，`coverImage` 仍为 `null`（M4 时用占位图） |
| 食材无法拆出用量（没有数字） | `amount` 留空（界面上显示"适量"）——这是原文的真实情况，不补造 |
| 源仓库升级导致格式变化 | 导入器对缺失小节**不报错**，只跳过对应字段；输出统计 |
| 中文与数字之间空格等排版差异 | 归一化处理，不算解析失败 |

## 6. 验收标准

## 8. 风险、回滚与依赖

- **风险 1：来源许可** → 已裁定只用 Unlicense 的 HowToCook；不碰无许可仓库。
- **风险 2：数量淹没自建菜谱**（372 道 vs 现有 2 道）→ 解析靠搜索/分类；自建菜谱 `source` 为"家常做法"，可区分。**范围由用户在 §9 决定**。
- **风险 3：机械解析出的元数据失真**（如把描述里的"美容效果"当 summary）→ 只取原文，不加工；抽样人工核对。
- **回滚**：菜谱文件在 git 里，`git rm` 即可整体撤销；图片目录同理。
- **依赖**：新增 devDependency `pinyin-pro`（仅导入脚本用，不进运行时）；不新增运行时依赖。

## 9. 已确认的决定（2026-09-20）

1. **导入范围：全量 371 道**（372 去掉官方 `template/`）。
2. **`id` 用拼音**（`hong-shao-rou`）：URL 可读；重名时追加序号。
3. 卡路里字段**不导入**（本项目数据模型没有该字段；不臆造）。
4. 导入的图片**不进 git**：`data/images/` 加入 `.gitignore`（约 108MB 二进制，随 `data/` 目录一起备份即可，不必让 git 仓库变重）。

### 实现过程中撞到并修掉的解析缺口（试跑 19 个失败 → 0）

| # | 问题 | 修法 |
| --- | --- | --- |
| 1 | 目录有**两种层级**（`分类/菜名.md` 171 个 + `分类/菜名/菜名.md` 201 个），只找到 200 个 | 递归遍历 |
| 2 | 份量口径**并不统一**（模板说 2 人，实际有 1 人/3 人/范围） | 逐文件解析 `够 N 个人…`，范围取下限；未声明记 2 并注明 |
| 3 | 中文数字用量（`葱 一根`、`姜 一块`）被当成名称一部分 | 支持中文数字；名称里含数字（`五花肉`）也正确切分 |
| 4 | 括号里的数字被当成用量（`虾 250g * 份数（建议 1-2 人份）`） | 先摘括号，再以空格为界找数量 |
| 5 | 步骤正文写在子要点里 → 步骤文本为空（6 个文件） | 正文为空时用子要点当正文 |
| 6 | 「计算」按阶段分组（`### 腌料`）导致同名食材被判重复（10 个文件） | 分组带进 `Ingredient.group`；重复规则降为警告 |
| 7 | 名称里带 `=`（`- 淀粉 = 1 汤匙`） | 清理名称尾部符号 |
| 8 | 列表符号有 `-` `*` `+` 三种 | 三种都认 |
| 9 | 图片只在前言里找、且只有 179 个文件写了图片引用 | 全文查找 + 「菜名.后缀」+ 单图目录回退 |
