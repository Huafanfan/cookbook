## 1. 目标与非目标

### 目标

- 先为血浆鸭、孜然牛肉、西红柿牛腩、美式炒蛋补齐封面，在已有列表和详情页直接显示。
- 每张图都有可追溯记录；来源图优先，AI 图的“AI 示意图”标识在图片内永久可见。

### 非目标

- 本批不一次补齐全部缺图，不改菜谱内容，不覆盖任何已有图片，不制作步骤图。
- 不引入网页上传、外网运行依赖、图片元数据 API 或新依赖。
- 本轮范围是本地素材与验证，服务器部署和推送另需明确指令。

## 2. 用户场景与状态流

用户在电脑或手机上浏览菜谱、挑选要做的菜：卡片原本无图 → 本地加入审核通过的封面并重启服务 → 卡片与详情显示封面 → 查看食材和步骤。AI 图片用于辅助识别与激发兴趣，不作为真实试做证据。

## 3. 交互细节与状态

| 状态 | 表现 |
| --- | --- |
| 有来源照片 | 既有封面组件显示照片 |
| 有 AI 图 | 既有封面组件显示带“AI 示意图”的素材；标识安排在中心裁切保留区域 |
| 无图 / 加载中 / 失败 | 沿用 [CB-007](CB-007-images.md) 的占位与失败降级 |
| 手机 / 桌面 | 不改变布局、点击区域和做菜交互；检查中央裁切仍能辨识菜品与标识 |

## 4. 数据与接口变化

| 变化 | 内容 |
| --- | --- |
| 菜谱字段 | 无；现有 JSON 保持原字节 |
| API | 无新字段；沿用启动扫描派生的 `coverImage` |
| 图片目录 | 沿用 [DATA_MODEL §4](../DATA_MODEL.md#4-图片约定已实现cb-007)；仅新增四张标准 JPEG |
| 来源记录 | 每张素材的来源、审核、提示词、文件哈希与尺寸集中记录在 [验收记录](../verification/CB-012/CHECK.md) |

旧菜谱无需迁移，图片继续不进 git；本地资产需要随 `data/` 备份。

## 5. 失败、降级与边界

| 情形 | 行为 |
| --- | --- |
| 来源或做法不能确认 | 不采用，记录拒绝理由 |
| AI 图食材明显不符或标识错误 | 不落盘，修正后重审 |
| 目标封面已存在 | 停止该项写入，保留现有资产 |
| 格式或解码失败 | 不采用；重新转换/验证 |
| 图片加载失败 | 既有 CB-007 降级，不影响食材和步骤 |

## 8. 风险、回滚与依赖

- 风险：AI 图只是外观示意，不能证明做法或最终成品；部分缺图仍需后续逐道寻找素材。
- 回滚：本批均为新增，需撤回时将四张素材移到备份位置，再重启本地服务；不删除旧数据。
- 依赖：CB-007 图片扫描与托管；系统 `sips` 只做离线 JPEG 编码与等比例缩放。

## 9. 实施拆解与顺序

1. 盘点当前缺图；逐张核对上游候选，保存实施前哈希。
