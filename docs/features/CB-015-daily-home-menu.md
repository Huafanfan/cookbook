## 1. 目标与非目标

### 目标

- “我的厨具”收为与工坊同尺寸的精美图标，点击仍展开原厨具设置。
- “今晚，做点好吃的”下方展示一组适合两人的家常搭配，默认荤菜、素菜、汤各一道，全部能打开现有菜谱详情。
- 使用 DeepSeek-V4.1-Flash，从服务内已载入菜谱中选择；一天同一组，两台设备一致，刷新页面和重启不额外重复模型请求。
- 推荐更新或失败时，首页的搜索、菜谱浏览和详情继续可用。

### 非目标

- 不让模型编新菜、改写菜谱、调整用量或上传图片，不新增数据库、路由库、图标依赖或其他模型提供方。
- 不新增饮食健康承诺、营养计算、购物清单、人数设置、手动换一桌按钮或公网入口。
- 当前按两人、一荤一素一汤理解；主食由用户按习惯另备。现有菜谱原始份量和用量保留。

## 2. 用户场景与状态流

主要在选晚餐时打开首页，先看两人的完整搭配，再点菜查看做法；手机也能看到三道菜，不隐藏第二、第三道。

```text
服务启动 → 读取菜单与日期预算 → 缺少当日记录时后台生成
每天北京时间00:05 → 后台刷新一次 → 校验现有菜谱ID → 持久化菜单
首页 → 立即显示缓存或普通搭配 → 更新完成后显示今日菜单 → 点击进入原详情
```

启动只补缺失的当日菜单；真实请求前先持久化当日预算。每日最多一次生成尝试，失败或重启中断保留上一组/普通搭配，到下一日再尝试，不自动重放收费请求。

## 3. 交互细节与状态

| 状态 | 表现 | 说明 |
| --- | --- | --- |
| 默认 | 原标题、简短日期/“2人餐”、三张带角色的菜图卡片 | 移除固定三菜；不展示模型配置、提示词或预算细节 |
| 厨具图标 | 绿色厨具轮廓、44×44px淡色圆角底；同名焦点/悬停提示 | 可访问名称“我的厨具”、aria-expanded，Enter/Space可展开 |
| 更新中 | 显示已有菜单或普通搭配，简短“今日搭配准备中” | 首页不等待模型；仅更新中短暂轮询读接口 |
| 模型失败 | 有旧菜单时显示其原日期；否则显示普通搭配 | 不把降级搭配标作今日AI推荐 |
| 无候选/接口失败 | 不显示空卡或伪造菜；给出简短提示 | 普通菜谱列表照常工作 |
| 搜索/筛选 | 推荐区暂时隐藏，继续呈现搜索结果 | 推荐不跟随关键词额外请求模型 |
| 菜谱被外部移除 | 返回有效旧菜单或普通搭配 | 不展示失效ID，不额外消费当日预算 |

桌面三张卡并列，手机也显示整组可点击卡片及菜名、角色；320px/390px无横向溢出。沿用白底、绿字、真实封面与现有字体，长菜名可换行/省略，完整名称保留在可访问名称中。

## 4. 数据与接口变化

- 既有Recipe、图片和用户状态字段不变，不改371道原文件。
- 新增 `GET /api/daily-menu`；返回两人菜单、实际菜谱摘要、日期、来源和可读状态。GET只读已有状态，不按访问次数调用模型。
- 新增服务派生的 `data/recommendations/daily-menu.json`，字段与样例以 [DATA_MODEL §10](../DATA_MODEL.md#10-每日菜单与请求预算cb-015) 为权威位置。文件不进Git/镜像，随完整data备份。
- 类型在 `src/shared/types.ts`，所有结构校验在 `src/server/lib/schema.ts`；文件读写只新增在已有repository中。

## 5. 失败、降级与边界

| 情形 | 处理 |
| --- | --- |
| DS未配置 | 不发送请求，普通搭配可用，厨具/工坊原功能保持 |
| 超时、401/429/5xx、非法JSON、重复/虚构ID | 当日记录失败；保留旧成功菜单或普通搭配，不重试收费请求 |
| 缓存不可读/不可写 | 不影响启动；不在无法持久化预算时调用模型，不覆盖坏缓存 |
| 重启时仍在生成 | 同日不重放；显示旧菜单/降级，下一天正常尝试 |
| 并发请求/两个服务对象 | 同一repository串行认领日期，最多一个模型调用；部署仍是单进程单副本 |
| 厨具设置变化 | 新一日参考最新设置；当日菜单不再次付费更新，卡片继续显示当前厨具匹配 |

候选为家常菜及汤羹（兼容手动“汤”分类），优先两人份、原有厨具可做的简单菜。排除饮品、甜品、调料和半成品。仅发送选菜所需的名称、分类、份量、食材名、厨具、标签/时间摘要；不发送草稿、历史、点赞状态、图片、来源链接或密钥。具体调用/候选预算与防护见ADR。

## 7. 测试要点

单元与集成覆盖模型请求契约、候选ID校验、日期边界、并发认领、重启预算、坏缓存/写失败、降级与卡片导航。真实模型单次试验记录返回用量与选菜结果；不写正式菜谱。浏览器检查图标、整桌卡片、搜索隐藏/恢复与控制台。

## 8. 风险、回滚与依赖

模型会误判口味/菜量；由用户按实际食量确认。保存结果只包含现有菜的引用，无法修改原菜谱。代码回滚可停用每日任务，保留所有菜单缓存、用户菜谱和草稿。复用现有DS环境、Node fetch、zod及数据挂载。
