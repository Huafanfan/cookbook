## 1. 一句话目标

自用菜谱网站：**浏览或搜索选中一道菜 → 点进去看到简单明了的制作步骤**。
部署在本地服务器的 Docker 中，局域网内任意设备（手机、平板、电脑）用浏览器访问，无需登录。

## 2. 用户与场景

| 项 | 说明 |
| --- | --- |
| 使用者 | 本人及家人（个位数，无账号体系） |
| 典型场景 | 站在厨房里，用手机打开，找一道菜，照着做 |
| 使用频率 | 每天 1～3 次，单次停留 1～5 分钟 |
| 网络环境 | 家庭局域网 `192.168.1.0/24`，服务器固定 IP `192.168.1.2` |
| 设备 | 手机为主（竖屏、单手），电脑为辅（浏览、录入） |

场景决定了三个硬性约束：

1. **手机优先**：竖屏、大字号、大点击区域，厨房里可能手湿/戴手套。
2. **快**：局域网内首屏 < 1 秒，搜索输入即时出结果（无需按回车）。
3. **能离线做菜**：浏览、搜索、手动录入与已有菜谱不依赖外网。创意工坊的公开链接提取/DS整理及每日菜单生成使用受控出站；失败不挡浏览，范围见 [CB-014](features/CB-014-recipe-workshop.md) 与 [CB-015](features/CB-015-daily-home-menu.md) 及其关联ADR。

### 3.5 明确不做

- 不做用户注册/登录/多租户。
- 不做互联网公网访问（局域网自用；如需外网，另行讨论 Tailscale 方案）。
- 不做社交、评论、评分或自动批量爬取；用户提交单份公开来源的提取属于 CB-014。
- 第一期不引入数据库（JSON 文件足够，见 `ARCHITECTURE.md` 的取舍说明）。

## 4. 验收标准

第一期完成后，应能通过以下检查（每条都可实测）：

1. 手机连家里 Wi-Fi，浏览器打开 `http://192.168.1.2:<端口>/`，**3 秒内**看到菜品列表。
2. 在搜索框输入"西红柿"，**边输边出现**"西红柿炒鸡蛋"，点进去能看到全部食材与步骤。
3. 输入"鸡蛋"（食材名）也能搜到西红柿炒鸡蛋。
4. 详情页步骤清晰：每条步骤一眼一行，编号明确，火候/时间不丢失。
5. 手机竖屏下**无需横向滚动**，主要按钮点击区域 ≥ 44px。
6. 新增一道菜 = 往 `data/recipes/` 放一个 JSON 文件 + 重启容器，无需改代码、无需重新构建镜像。
7. 服务器重启后服务自动恢复（`restart: unless-stopped`）。
8. 备份 = 打包 `data/` 目录（含图片），恢复即还原全部内容。

## 5. 非功能要求

| 项 | 要求 |
| --- | --- |
| 性能 | 局域网首屏 < 1s；搜索响应 < 50ms（本地内存索引） |
| 容量 | 支持 1000 道菜、2000 张图片无压力 |
| 安全 | 仅局域网可访问；容器非 root、只读根文件系统、无多余能力（沿用现有部署约定） |
| 可维护 | 单人可维护；不引入需要长期升级的复杂依赖 |
| 可移植 | 数据与代码分离，`data/` 可整体拷走 |
| 兼容 | 手机 Safari / Android Chrome，桌面 Chrome / Safari 主流版本 |

## 6. 术语

| 词 | 含义 |
| --- | --- |
| 菜品 / 菜谱 | 一道可以做的菜，本项目的核心数据单元 |
| 食材 | 主料与调料，统一用 `ingredients` 表达，带 `group` 区分 |
| 步骤 | 有序的操作说明，每条尽量一句话，可带火候、时间、提示 |
| 分类 | 单值，如"家常菜" |
| 标签 | 多值，如 `["快手", "下饭"]` |
| 别名 | 同一道菜的其他叫法，用于搜索（如"番茄炒蛋"） |
