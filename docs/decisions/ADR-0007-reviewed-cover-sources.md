# ADR-0007：逐张审核封面来源与 AI 示意图

## 状态

已接受，2026-09-30。用户要求继续此前的小批补图结论；实施范围见 [CB-012](../features/CB-012-cover-backfill.md)。

## 背景

已有图片来源与目录规范见 [DATA_MODEL](../DATA_MODEL.md)。仍有菜谱缺封面；来源仓库中有些多图未被导入，有些图片的配料或具体做法与现有菜谱不符。仅凭菜名搜索或目录同名不足以确认匹配。

## 决策

1. 优先采用来源和许可可核实、与当前菜谱的主要食材和做法对应的真实图片。核对固定提交、图片本身和菜谱，记录选择与拒绝理由。
2. 没有合适真实图片时，可以按当前食材和步骤生成 AI 外观示意图，逐张检查明显错误。必须永久写入“AI 示意图”标识，并验证列表、详情裁切保留标识；不得描述为真实试做照片。
3. 本批标识嵌入图片，不新增图片来源 API 字段或改动菜谱 JSON。以后如需可访问的语义标识或网页管理，应另立规格。
4. 图片继续作为 `data/` 资产，不进 git、不进镜像；来源、生成提示词、SHA-256、尺寸与审核证据随文档版本化。逐张记录的权威位置是对应批次 CHECK。
5. 只新增审核通过的封面，不覆盖旧图片，不自动批量套图。图片仍由既有扫描与白名单提供，沿用 [ADR-0004](ADR-0004-image-static-hosting.md)。

## 后果

- 不改应用运行架构、数据结构或网络暴露面；本地新增文件与重启即可生效。
- AI 图片会有外观偏差，审核只能筛掉可观察的明显问题，最终观感由用户判断；不能替代厨房反馈。
- 图片内的标识无法作为独立文本供屏幕阅读器读取；本批没有新增相应 API/组件。后续若扩大 AI 覆盖，应考虑独立来源元数据与可访问标识。
- git 提交仅保存文档证据，素材备份仍依赖 `data/`。部署和数据删除需另获明确授权。
