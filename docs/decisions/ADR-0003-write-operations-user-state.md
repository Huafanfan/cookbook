# ADR-0003：引入写操作 —— 用户状态存服务端

## 状态

已接受（2026-09-20，用户明确选择"服务端（两人共享）"）

## 背景

菜谱数据一直是**只读**的：应用启动时把 `data/` 读进内存，运行期只写日志。这是 [ADR-0002](ADR-0002-json-files-as-source-of-truth.md) 明确记录的前提（"只有一个写者，且写入极少"），容器也因此用 `read_only: true` 挂载数据目录。

现在要加**点赞与收藏**，并且用户要求**两口子共享**（在手机上收藏的菜，电脑上也应该排到前面）。这意味着：

1. 应用运行期要**写数据**（新增一类持久化状态）；
2. 数据目录需要**可写挂载**（当前是只读）；
3. 出现**并发写**的可能（两个人在各自设备上几乎同时点赞）。

按 ADR-0002 的约定，这属于必须新开 ADR 的变更。

## 决策

### 1. 用户状态与菜谱内容**分开放**

| 数据 | 位置 | 谁写 | 说明 |
| --- | --- | --- | --- |
| 菜谱内容 | `data/recipes/*.json` | 导入脚本 / 手工编辑 | **运行期仍然只读**，容器以只读方式挂载这一部分 |
| 厨具词表 | `data/equipment.json` | 手工编辑 | 只读 |
| **用户状态** | `data/user-state.json` | **应用运行期写入** | 点赞数、收藏标记 |

**关键**：菜谱内容与用户状态分开，意味着"写操作"的影响面被限制在一个文件里 —— 菜谱数据的完整性与可版本化（ADR-0002 的好处）不受影响。

### 2. 存储形态：**一个 JSON 文件 + 原子替换**

```json
{
  "version": 1,
  "recipes": {
    "hong-shao-rou": { "likes": 3, "favorite": true, "updatedAt": "2026-09-20T12:00:00.000Z" }
  }
}
```

- 写入方式：**写临时文件 → `rename` 原子替换**（同目录内），避免半个文件导致下次启动读不出来。
- 内存里保持权威副本；每次变更后**同步落盘**（不批量、不延迟）。
- 文件读不出来（损坏/不存在）→ 用空状态启动并**把损坏文件另存为 `.broken`**（不静默丢弃用户数据）。

### 3. 并发与冲突

- 单进程、单文件、内存权威副本 → 用**串行写队列**（同时只有一个写在跑），后到者等待。
- 冲突语义：`likes` 是**计数增减**（`+1 / -1`，下限 0），不是"设置成某个值"，因此天然可合并。
- 不引入锁文件、不做多进程协调 —— 本应用只有一个进程（见"边界"）。

### 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/user-state` | 全部用户状态（前端一次拿全，用于排序与标记） |
| `POST` | `/api/recipes/:id/like` | body `{ "delta": 1 \| -1 }`；幂等由前端保证（本地记录已点赞） |
| `POST` | `/api/recipes/:id/favorite` | body `{ "favorite": true \| false }` |

- 这些是**本项目第一个写接口**，因此：只接受 `POST`、只接受 JSON、**`id` 必须已存在**（否则 404）、body 严格校验（未知字段拒绝）。
- **不做鉴权**：局域网自用，与只读接口一致的信任模型（见"后果"里的风险）。

### 5. 容器与部署影响

- 数据目录改为**可写挂载**（去掉 `read_only`），但容器根文件系统仍 `read_only: true`（`/tmp` 用 tmpfs）。
- 备份仍然只需打包 `data/`（`user-state.json` 会一起进备份）✓
- 写入位置固定为 `/data/user-state.json`。

## 后果

**好处**：两口子共享收藏与点赞；数据仍是一个可打包的目录；菜谱内容不受写操作影响，仍可版本化。

**代价与必须接受的风险**：

1. **数据目录不再只读** —— 容器被攻破时理论上能改数据文件。局域网自用场景下接受；若将来要暴露到公网，必须先补鉴权（那时新开 ADR）。
2. **无鉴权** → 同网段任何设备都能点赞/取消。这是"局域网自用"的既有信任模型（与只读接口一致），不是新增暴露面。
3. **单进程假设** —— 若将来跑多个副本，串行队列与内存副本会失效，必须改为文件锁或数据库（新 ADR）。
4. **写入失败必须让用户看见**：写不下去（磁盘满/权限错）时接口返回 5xx，前端明确提示"这次没能保存"，不得静默成功（复刻 CB-002 的 P1-5 教训）。

**明确不做**：不做用户账号、不做多用户区分（"谁点的赞"不记录）、不做评论。
