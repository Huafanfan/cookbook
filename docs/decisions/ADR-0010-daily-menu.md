# ADR-0010：每日家常菜单采用日期认领、DS选ID与本地缓存

## 状态

已接受（2026-10-03），关联 [CB-015](../features/CB-015-daily-home-menu.md)。用户明确要求每天由DS4.1基于现有菜谱推荐两人家常餐桌。

## 决策

1. **模型只选现有菜。** 复用现有DS环境与服务端配置读取；模型固定为 `deepseek-flash`，官方说明此接口对应V4.1-Flash。发Chat Completions、关闭thinking、JSON输出、最多800输出tokens、60秒总超时；一次尝试不自动修复/重试。密钥不进日志、缓存或前端。
2. **菜谱是候选而非模型指令。** 服务端构造家常菜/汤候选，优先现有厨具与两人份；摘要仅含必要字段。候选最多180道，总请求文本最多60000字符，保留汤与素菜选择，不下载外部内容。模型不得提供工具调用、改菜谱、猜用量或营养指标；结果经schema、角色唯一、ID唯一与候选白名单检查。
3. **每天北京时间一份。** 启动补缺失当日记录，之后00:05触发；用Asia/Shanghai日期，不依赖宿主机时区。只在Fastify真正onListen后运行，app.inject不会意外触发收费；关闭时清定时器并取消未完成请求。
4. **认领先落盘。** repository串行读取/认领日期；生成前保存`generating`记录，完成或失败原子替换。任何同日期记录均阻止新模型调用；进程崩溃后不重放。前提为当前单副本部署，不声称支持多进程分布式认领。
5. **缓存是独立派生文件。** 保存每个日期的状态和成功菜单引用，保留旧记录便于重复规避和审计；无自动清理。全部文件I/O在recipe-repository，字段权威位置见DATA_MODEL。坏文件保留、告警和降级，不影响应用启动或以重写恢复为由覆盖数据。
6. **浏览是只读。** GET返回当日/最近有效菜单或确定性普通搭配，按现有ID实时关联摘要；模型不在GET里启动。普通搭配明确标识，当前无完整组合时可为空；缺失菜谱不得伪造补齐。搜索时隐藏推荐区，但服务端每日任务继续运行。

## 后果与取舍

优点：每台设备共用、重启不重复消费、失败不挡首页，无新依赖/数据库/常驻调度服务。代价：失败的一天不会自动重试，修改厨具也要等下一天重新选菜；模型质量需要用户实际反馈。日期缓存占用随使用增长，后续清理需另行设计。
