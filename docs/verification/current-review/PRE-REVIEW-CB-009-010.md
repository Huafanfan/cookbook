### CB-009：写入与历史

| # | Astra 的意见（要点） | 处置 |
| --- | --- | --- |
| 1 | **哈希不能保证任意外部写者的并发安全**。要在 repository 的**每菜谱串行队列**内：重新读盘 → 比完整 SHA-256 → 校验 → 保存历史 → 替换 → 更新内存；并**明确保证范围**（应用内串行；手工编辑/导入必须停服或走同一受控入口）。仅"读后比哈希再 rename"仍有 TOCTOU 窗口，**不得宣称能阻止编辑器同时覆盖** | 待修：ADR-0005 §1/§3/§4 写清"保证范围"与 TOCTOU 边界；CB-009 §5 增加"外部同时写"的诚实结论 |
| 2 | **历史与当前文件不是原子事务**。明确提交点 = 当前菜谱 `rename` 成功；历史失败 → 当前文件不变；历史成功、替换失败 → 允许保留未完成操作的历史记录并注明语义；**替换成功后不得再返回"已恢复原状"**（请求中断/响应丢失要提示"结果未确认，重读确认"）。历史用**独立唯一 historyId**（随机或时间戳+随机、独占创建），**不能用内容 revision 当历史 ID**（同一内容会重复出现）。记录格式含 `beforeRecipe`/`beforeRevision`/`afterRevision`/时间/操作类型/备注。**不要承诺自动 Git 提交** | 待修：ADR-0005 §5 重写提交点与失败语义 + historyId + 记录格式 |
| 3 | **409 的"覆盖"不能绕过守卫**：确认后携带**最新** `currentRevision` 再提交，若又有人改 → 继续 409；保持草稿，不 force-write。请求 schema 严格校验；`recipe.id` 必须等于 URL id（**禁止重命名**）；图片 URL、revision、未来受保护的来源元数据**不能被表单覆盖、也不能被 zod 静默删除** | 待修：CB-009 §4 接口签名与"受保护字段"清单 + §5 覆盖流程 |
| 4 | **补齐现有数据约束**：`createRecipeSchema` 不含 `check:data` 的全部内容检查 → 保存还须调用**现有 blocking content lint**；词表失败必须**服务端拒写**（不能只禁用前端按钮）；写后要同步**搜索/meta、图片索引、客户端缓存**；**步骤增删重排会让 `step-N.jpg` 与 sessionStorage 完成索引指错** → 必须先定降级/重关联规则；草稿应存 `{recipeId, baseRevision, draft, savedAt}`，localStorage 写失败要**可见**，恢复草稿不能换掉旧 `baseRevision` | 待修：ADR-0005 §2、CB-009 §4/§5/§7 |
| 5 | **不要只给旧导入器贴警告**：CB-010 前至少**默认拒绝覆盖已有菜谱**（需显式开关），或把"覆盖导入"与"运行中编辑"明确互斥。无鉴权内容写入风险高于点赞：保持现有端口，加入**同源请求保护**、JSON 类型限制与**请求大小限制**，不新增监听暴露面 | 待修：ADR-0005 §7 + CB-009 §4/§8（安全项） |

### CB-010：基线与 LLM

| # | Astra 的意见（要点） | 处置 |
| --- | --- | --- |
| 6 | **不能把今天的上游 HEAD 冒充历史导入基线**。当前菜谱已有 tag/时间等后续改动；名称唯一只证明"候选来源"，**不能证明 baseline**。回填要分开记录"来源已匹配"与"基线已验证"；无法证明历史基线的菜**不得自动覆盖**，进入**人工建立基线**流程 | 待修：ADR-0006 §3、CB-010 §4/§5 |
| 7 | **原始文件哈希与语义哈希必须分开**：`revision`（并发控制）用原文件**完整字节哈希**；三方比较必须统一 **canonical 内容投影**，排除 `sourceRef`/时间/派生字段，并定义应用维护字段（tag/厨具归一化）的**所有权**；否则一加来源字段就永远判"本地已修改"。记录 **parser/normalizer 版本**。建议**保存一份实际解析后的基线快照**；不存快照则必须固定解析器版本 + 完整 commit OID，并说明 `data/` 备份已不足以独立恢复同步能力 | 待修：ADR-0006 §1/§2/§4、CB-010 §4 |
| 8 | **冲突不可用 `--accept-conflicts` 一键绕过**：首版**移除**该选项；未决冲突必须**逐项解决**；数组重排/删除**不能按下标合并**；提案需唯一 ID + base/local/upstream 哈希 + 模型与参数 + 解决状态；应用时**重新校验本地 revision**，并走**与网页相同的保存/历史路径**；LLM **不得决定** id、来源基线、文件路径、审计来源 | 待修：ADR-0006 §5/§6、CB-010 §3/§5/§6 |
| 9 | **严格使用用户指定的 Luna low**：`/models` 列表**未证明** `reasoning_effort: low` 可用 → 用**无私人内容的最小请求**验证（**已做，见上表：可用**）；若被拒 → **报配置阻断，不要自动去掉 low**。只把**目标菜谱的三方内容**发给接口，不发送环境、密钥或其他文件。提示词**不能保证**"无新增事实"，zod 只能验结构 → **人工逐项审阅是必要门禁**；默认 **dry-run、单菜处理**；批量回填/覆盖真实 `data/` 前**单独取得操作授权** | 待修：ADR-0006 §7、CB-010 §4/§5/§6 |
