## 2. 真实浏览器验收（隔离实例，2026-09-21）

| # | 操作 | 结果 |
| --- | --- | --- |
| 1 | 详情页 →「✎ 编辑」→ 表单预填 | ✅ 菜名「测试菜」、盐用量「2」等字段正确预填 |
| 2 | 改用量 2→5 + 填写改动说明「盐 2g → 5g」→ 保存 | ✅ 回到详情页显示「盐 5g」；磁盘 `amount: 5`、写入 `updatedAt`；`data/history/recipes/test-dish/20260921T134139Z-c5de-manual.json` 出现 |
| 3 | 「🕘 修改记录」 | ✅ 列表显示时间 + 来源「网页修改」+ 说明（截图 `history-list.png`） |
| 4 | 点开那一条 → 只读展示旧版（盐 2g） | ✅ 页面无输入框（只读）；旧版内容来自记录里的 `beforeRecipe` |

| 6 | **409 不静默覆盖**：在编辑页把盐改成 9 → 从外面直接改文件（模拟另一台设备/手工编辑，改名字与贴士）→ 点保存 | ✅ 出现冲突面板（「服务端上已经是另一个版本」，两个按钮：重新加载 / 用我的覆盖）；**磁盘内容未被覆盖**（仍是外面那版，盐还是 2）；截图 `edit-conflict.png` |
| 7 | 冲突面板点「重新加载（放弃我的改动）」 | ✅ 表单变成**磁盘上的版本**（名字 = 外面改的）——**修掉的问题**：原实现重新 GET 会拿到内存里的陈旧版本（应用只在启动时读文件），已改为用 409 响应里带的磁盘版本 |

## 3. 过程中修掉的真问题

| 问题 | 怎么发现的 | 修法 |
| --- | --- | --- |
| 非 JSON 请求体没被拒（Fastify 不替我拒） | HTTP 层测试（413/415 那组） | 写接口显式要求 `content-type: application/json`，否则 415 |
| 同一秒两次保存导致历史列表乱序 | 自己的测试（按文件名排序） | 改为按记录里的 `savedAt`（毫秒）倒序 |
| 冲突后「重新加载」显示陈旧内容 | 浏览器验收第 6/7 步 | 用 409 响应里的 `current`（读盘解析结果）而不是重新 GET |
