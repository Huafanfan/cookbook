## 1b. 真实模型路径（2026-09-21 补验，人工构造冲突）

因为上游 HEAD 与导入时是同一提交，冲突是**人工构造**的（基线 `servings=3` / 本地 `9` / 上游真实值 `1`），

| 步骤 | 结果 |
| --- | --- |
| `--propose --only chao-liang-fen` | ✅ 生成 `sync-proposals/<proposalId>.{json,md}`；日志显示"请 gpt-5.6-luna（low）合并 1 处冲突" |
| 提案内容 | ✅ `conflicts: [servings（基线 3 / 上游 1 / 本地 9）]`；**可疑值（两边都没有）为空** |
| LLM 的说明 | ✅ 明确写出"**选择保留家里版本的 9**……标记为待人工决定"——**没有编造、没有偷偷选上游**，还主动保留本地拥有的 `sourceRef` |
| 给人看的审阅件 | ✅ `.<proposalId>.md`：菜谱/上游提交/模型与档位/三方语义哈希 + 冲突逐条 + 可疑值 + 落地命令 |
| 未解决冲突时 `--apply` | ✅ 被拒："提案里还有 1 处未解决冲突（servings）——先逐项解决再落地（首版没有一键绕过）"（退出码 1，单独复核） |

| 人工逐项解决后 `--apply` | ✅ 落地成功：`servings=9`（人工决定）、`sourceRef.commit` 更新、历史写出 **2 条**（`-llm-merge` + `-import`）、基线快照保留、`tags` 保留 |
| 真实数据 | ✅ 全程零改动（临时数据目录） |
